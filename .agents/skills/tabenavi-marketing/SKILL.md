# たべなび マーケティングスキル

## 戦略の現在地（2026-06時点）— まずこれを踏まえる

- 成長の主軸は**検索/需要捕捉**（SEO記事・/chainsハブ・北極星=GSCインデックス済みページ数）。SNSは補完であり、毎晩の量産はbusywork。**量より1本の質**。
- 動画は **2026-06-11に実写スマホ撮影方式へ転換済み**。AIスライドショー/モーショングラフィックス型は再生ほぼゼロで失敗が確定した方式であり、**今後のリール企画でAIスライドショー・AI生成画像ベースの動画を提案しない**。理由: ①AI料理画像は知覚価値を下げる（査読研究あり）うえ、食ジャンルの上位バズ事例にAIスライド型は0本 ②静止画構造は最重要シグナルの視聴維持を原理的に稼げない ③完璧に整った「広告の見た目」は0.5秒で防御反応を起こす ④発信人格が出ない ⑤エンゲージ設計を企画に埋め込めない。
- リール制作の詳細手順は `~/tabenavi-reels/REELS_PLAYBOOK.md`（汎用プレイブック）と `~/tabenavi-reels/VIRAL_REEL_PACKAGE_2026-06.md`（個別企画の完成形サンプル）。**リール/動画の依頼が来たら、まずこの2ファイルを読む。**

## ブランドガイドライン

### トーン＆ボイス
- 知的だが親しみやすい
- データドリブン（具体的な数字を必ず含める。「ヘルシー」ではなく「259kcal」）
- ポジティブ（「ダメ」「禁止」ではなく「こうすれば良い」）
- 外食を肯定する（外食＝悪ではない、選び方次第）

### ターゲットペルソナ
1. 筋トレ外食マン（25-35歳男性、週3ジム、昼夜外食）
2. ダイエット会社員（25-40歳、ランチ外食中心）
3. 健康意識ファミリー（30-45歳、家族で外食多い）

### ブランドカラー（2026-06更新 — 旧orange-500定義は廃止済み）
- 基準はライブサイト tabenavi.jp ＝ **sky/cyan系**（sky-400→cyan-500グラデーション、sky-50背景、sky-600テキスト）
- 栄養の色分け: タンパク質=blue、脂質=amber、炭水化物=green（サイト・動画テロップ共通）
- 動画内でのブランド色（ティール/シアン）は**アプリ画面紹介パートと「決め」テロップのみ**に限定する。一般カットにまでブランド色を載せると「広告の見た目」になり防御反応を招く

### 禁止事項
- 競合サービス名を出さない（あすけん、MyFitnessPal等）
- 「ダメ」「禁止」等の否定的表現を避ける
- **数値・実績・評価・体験談の捏造は絶対にしない**。過去に捏造aggregateRating・架空の「ユーザーの声」をサイト監査で全削除した経緯がある。実レビューは収集後に出所明記でのみ使用可
- 偽の緊急性（「今だけ！」「先着○名！」等の煽り）を使わない

## 数値の取り扱い（全コンテンツ共通・最重要）

数値はたべなびの信頼の根幹。AIが記憶から出す栄養数値は誤りが多いことが運用で実証済みのため:

1. **DBの値のみ使う**。必ずSupabase `menu_items` を検算する（DBが単一の真実）。標準ツール: `node scripts/data-update/menu-lookup.mjs "<チェーン名>" ["<商品名の一部>"]`（リポジトリ内で実行）。※Supabase MCPは別プロジェクト(Qurio)を指すため使わない
2. **派生値（×2・差分・合算）は派生であることを注記する**（例:「※単品値の2倍加算」）。キャプションや固定コメントに出典を書く
3. 差が極小の比較（タンパク質0.5g以下・10kcal以下）は「同じ」と断定せず**「ほぼ同じ／ほぼ同値」で全成果物（テロップ・キャプション・カバー）を統一**する
4. 動画は**撮影当日にレシート実物と公式サイト表記で最終確認**。価格改定があれば差額系の数字（「¥120安い」等）をすべて再計算して差し替える。価格改定時は栄養値も公式ページで再照合する（リニューアルで栄養値が変わることがある）
5. 画面に出す規模の主張（「全207品」等）は当日ライブサイトで照合する。照合できなければ「全メニューPFC入り」等の非数値表現に逃がす

## リール/TikTok制作ルール（実写プレイブック準拠）

フル手順は `~/tabenavi-reels/REELS_PLAYBOOK.md`。以下は企画段階から守る骨子。

### 企画の合格条件（全部満たさない案はボツにする）
- **数値比較の緊張感**がある（A vs B。単なる紹介・豆知識はNG）
- 視聴者が答えたくなる**「割れる二択」**がある（どちらも擁護可能で、自分ごとになる）
- **実写で証明できる**（実食・レシート・実機画面録画・価格が映る）
- 22-30秒のアークに収まる（フック→証明→実食→種明かし→スクショ表→二択ループ）
- 固定コメントで先回りする反論が3個以上見込める

### フック（0-2秒）
- **0秒から手が動いている**。導入フレーム・タイトル画面は置かない
- 命令形テロップ（「〜買え」「〜送っとけ」）。**テロップは1行10-13字厳守**（親指スクロール速度での可読限界）
- 冒頭2秒で2カット。2カット目に情報（価格・比較画）を載せ「理由がすぐ来る」と予告する
- 迷ったらフック3案でA/Bテスト: 通常投稿で2-3日間隔、3秒維持率で判定（本体は共通、差し替えは0-2秒のみ）

### 本体構造
- **実食カット＋一言ボイス**（「うまい」「えっ」程度・顔出し不要）で人格を出す。広告ではなく実在の人間の飯だと確信させるため
- アプリは「宣伝」ではなく**「種明かし」**（「この数字、全部ここで調べた」）として**尺の13.6%以内**（22秒なら3秒、ジャンプカット2回に分割）
- DM共有の小テロップ（「○○行く友達に送っとけ」）は**損得が確定した瞬間（9-10秒付近）に0.8-1秒だけ**重ねる。メインの決めテロップより小さく
- ラスト: スクショ用の表をフルサイズ**2.5秒以上**→60%に縮小して残しつつ中央に二択質問→ループで冒頭の命令形が「答え」として再生される設計（最終フレームと冒頭フレームの構図を揃える）
- **同一画角を3秒以上続けない**
- 実写素材は自分のトレイ・実食・レシート・実機画面録画のみ。他の客・店員・店内引きは映さない

### 投稿・運用
- 投稿時間: 平日18:00-19:30（ジム後の閲覧帯）または11:30-12:30
- BGMはCapCutでなく**Instagram投稿時にアプリ内音源で付ける**（アルゴリズム優遇）
- 投稿直後に**固定コメント**で想定反論3-5個に先回り＋次回予告（コメント欄を次企画への投票に変える）
- **削除・再投稿は絶対にしない**（アルゴリズムへの失敗シグナル）。次の1本で変えるのは1変数のみ。フォーマット転換の判断は最低10-20本後

### KPI判定ゲート（24-72時間）
| 指標 | 合格 | 未達時 |
|---|---|---|
| 3秒維持率 | 50%+ | フック差し替え（B/C案） |
| 平均視聴時間 | 尺の50%+ | 維持率グラフで離脱フレーム特定 |
| シェア率（送信/リーチ） | 1.0%+ | 共有CTAの文言強化 |
| 保存率（保存/リーチ） | 1.5%+ | スクショ表の表示時間・設計見直し |
| コメント率 | 0.3%+ | 最後の二択質問を言い換え |

## X (Twitter) 投稿ルール

- 280文字以内、ハッシュタグ: #筋トレ飯 #外食ダイエット #マクロ管理 #たべなび
- 具体的な数字を入れ、意外性を作る。「保存して次行く時に使ってね」等の保存誘導
- 宣伝は全体の15%以下
- バズるフォーマット: ①「保存推奨」リスト型 ②「意外な事実」型 ③比較表型（A vs B）④ランキング型 ⑤アンケート/質問型
- 投稿時間: 朝7:00（通勤）/ 昼12:00（ランチ前）/ 夜20:00（翌日計画）

## 栄養データの参照方法（クイックリファレンスは廃止）

**このスキルに数値を書き置きしない。** 過去に本節へ置いたクイックリファレンスが古くなり、誤値（例: すき家牛丼ライト352kcal＝2026-06の捏造是正で誤りと確定した値、実際は並盛397kcal）やDB非存在商品（例: セブン「サラダチキン」）を含んだまま参照される事故が起きた。

数値が必要な時は毎回その場でDBを引く:
```
node scripts/data-update/menu-lookup.mjs "<チェーン名>" ["<商品名の一部>"]   # リポジトリ内で実行
node scripts/data-update/menu-lookup.mjs --chains                        # チェーン名一覧
```
- **PFC欠損チェーン**（サイゼリヤ・ガスト・くら寿司・スシロー・バーミヤン・日高屋・ステーキガスト）はP/F/CがDBに無い（0=未公開）。これらの特定メニューにP/F/C数値を付けたら捏造。カロリー・価格のみ使う。
- なか卯はDBに存在しない（言及しない）。
